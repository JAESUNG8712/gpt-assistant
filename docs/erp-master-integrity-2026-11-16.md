# ERP 재고 격리와 마스터 수명주기 보완

## 수정 범위
- PostgreSQL 재고 조회, 원장 조회, 조정, 실사, 이동, 견적 출고는 로그인 회사의 원장만 사용한다. 회사 미지정 행을 자동으로 귀속하거나 변경하지 않는다.
- 품목 삭제 시 재고 원장, 견적, 발주, 구매요청을 확인한다. 창고 삭제 시 원장과 문서의 위치 참조를 확인한다. 이력이 있는 자료는 삭제 대신 비활성화를 사용한다.
- 문서 생성/구매요청 발주 전환은 실제 참조가 존재하는지 검사한다. 자유 입력 견적 라인은 유지한다. PostgreSQL은 참조 FOR SHARE 잠금과 삽입을 같은 트랜잭션에서 실행하고 삭제는 FOR UPDATE 이후 다시 참조를 조회한다.
- JSON의 참조 검사/저장은 중간 await 없이 수행한다. 저장 성공 전에 메모리 상태를 공개하지 않는다.
- 품목/창고/영업목표를 삭제한 뒤 열린 편집창에서 일반 저장하면 409 ERP_MASTER_DELETED를 반환한다. restore:true를 명시한 경우만 복원한다. 문자열 true는 허용하지 않는다.
- JSON은 ERP 파일의 masterTombstones에 삭제 ID를 함께 기록한다. 재시작 시 삭제한 기본 창고도 다시 시딩하지 않는다. 기존 배포 전에 이미 삭제된 행의 이력은 복원할 수 없다.
- 브라우저는 삭제 충돌 시 복원 여부를 확인한다. 취소 또는 연결 실패 시 입력값을 유지한다.

## 검증
- 공통 JSON/PostgreSQL API 시나리오: 활성 자료 수정, 삭제 후 일반/문자열 restore 거부, 명시적 복원, 재삭제, 참조 문서 보존, 문서 생성/삭제 경합.
- PostgreSQL 전용: NULL/다른 회사 원장 배제, 부족 재고의 출고/이동 차단, 실사 증분, 타사/NULL 마스터 삭제 방어. CI의 별도 임시 데이터베이스에서 실행한다.
- JSON 전용: 저장 실패 원상 보존과 재시작 후 삭제 기록 유지.
- 브라우저: 품목/창고 편집 중 외부 삭제 → 복원 취소 시 입력 보존 → 명시적 복원 저장.
- 로컬 대상 API 테스트 36 통과, 실패 0, PostgreSQL 환경 의존 1 제외. 추가 재시작 포함 대상 테스트 13 통과, 실패 0, PostgreSQL 환경 의존 1 제외.
- 로컬 브라우저는 spawn EPERM으로 실행하지 못했다. 최종 PostgreSQL/브라우저 결과는 PR #179의 최신 CI를 기준으로 확인한다.

## 별도 후속 검토
- 기존 NULL 회사 마스터/문서 읽기 정책은 이번 변경으로 전면 변경하지 않는다. 소유 회사 식별과 백업 후 별도 마이그레이션/정책 결정을 해야 한다.
- 활성 마스터 간 동시 편집은 기존 마지막 저장 방식이다. 필드별 revision/CAS 도입은 삭제 충돌 보호와 별도 과제다.
- 기존에 참조가 이미 끊긴 문서는 이번 변경이 자동 수정하지 않는다. 운영 데이터의 읽기 전용 무결성 점검 후 복구 대상을 결정해야 한다.

## 기존 손상 문서의 재고 반영 차단
- 신규 구매요청의 품목 미선택 차단은 기존 동작을 유지한다.
- 이미 저장된 문서의 발주 전환, 입고, 출고에도 품목·창고 및 유효한 수량/단가 검증을 적용했다. 실패하면 문서 상태, 재고 원장, 세금계산서를 변경하지 않는다.
- 최신 로컬 대상 테스트: 19 통과, 실패 0, PostgreSQL 환경 의존 1 제외.
- 첫 CI의 실패는 NULL 회사 마스터를 생성하는 테스트 준비 단계에서 복합 기본키의 NOT NULL을 직접 해제하려던 오류였다. 임시 DB에서만 기본키를 동등한 UNIQUE 제약으로 바꾸어 과거 스키마를 재현하도록 수정했다. 운영 스키마 변경은 없다.
