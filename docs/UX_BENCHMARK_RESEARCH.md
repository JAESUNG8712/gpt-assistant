## 1. 전자결재 모듈

### 타 시스템 벤치마크 사례
- **결재선 오지정 → 승인 지연**이 국내 그룹웨어에서 가장 흔한 불만 축이다. "결재자가 자주 자리를 비우는데 승인 지연 문제는 없을까요"라는 도입 전 문의가 반복되고, 실제로 "결재선이 맞게 지정되지 않아 승인 시간이 길어져 의사결정이 지체되는" 사례가 보고된다.
- 반대로 결재선이 너무 촘촘하면 "결재선이 너무 복잡해서 전자결재가 오히려 불편"하다는 불만도 동시에 존재 — 즉 **자동 추천 + 예외적 수동 조정**의 균형이 관건.
- 하이웍스는 전자결재가 "가장 만족도가 높은 기능"으로 꼽히는데, 이유는 양식별 결재자 사전 지정(규정을 매번 확인할 필요 없음) + 인사관리 연동 + SMS/메일/메신저 실시간 알림 3박자 때문.
- 글로벌 Slack 기반 승인 워크플로우 비판: "다건가액 기준 VP 승인처럼 조건부 라우팅을 못 걸어서" 결국 수작업 확인이 필요해진다는 지적, "알림이 폭주하면 팀이 알림 자체를 무시하기 시작"한다는 지적.
- 더존 계열 ERP 리뷰: "UI/UX가 좋지 않고 새로고침 버튼 위치·아이콘 표현이 화면마다 일관성 없다"는 비판 — 결재/전표 화면 곳곳의 시각적 일관성이 신뢰도에 영향을 준다는 시사점.

### 이 앱에 적용 가능한 구체적 개선안
현재 앱은 이미 결재 위임(대결자 지정, `renderApprovalDelegationPage`)을 갖추고 있어 "결재자 부재 시 승인 지연" 문제의 절반은 해소돼 있다. 남은 격차는 다음과 같다.

- **[상] 결재선 자동 추천 근거 노출** — 문서 유형(연차/지출/구매요청 등)별로 결재선이 자동 세팅될 때, "왜 이 결재선인지"(직제 규정 근거)를 상신 화면에 툴팁/배지로 보여준다. 규정을 매번 확인하지 않아도 된다는 하이웍스의 핵심 만족 포인트를 재현.
- **[상] 결재 지연 임박 알림** — 상신 후 N시간(예: 24시간) 결재자가 미처리 상태면 결재자 본인 + 상신자에게 리마인드 알림을 보내는 배치. 현재 결재함(`renderApprovalInbox`)은 목록만 보여줄 뿐 SLA성 알림이 없어 보인다. 대결자 자동 치환(이미 구현됨)과 별개로, 대결자 미지정 상태에서의 방치를 줄이는 안전망.
- **[중] 조건부 결재선(금액/부서 기준 분기)** — 예: 지출결의 100만원 이상은 임원 결재 자동 추가. Slack 승인워크플로우의 약점("조건부 라우팅 불가")을 반면교사 삼아, 이 앱은 문서 유형별 고정 결재선에 금액 임계값 조건을 얹는 것을 권장.
- **[중] 결재 화면 시각적 일관성 점검** — 결재/회계/영업 등 모듈마다 버튼 위치·아이콘·배지 색상 규칙을 통일. (더존 비판의 반면교사)
- **[하] 결재 문서 초안 자동저장** — 작성 중 이탈 시 임시저장. 다우오피스·네이버웍스 등이 기본 제공하는 기능으로 사용자가 "당연히 있을 것"으로 기대하는 항목.

## 2. 커뮤니케이션(게시판/알림) 모듈

### 타 시스템 벤치마크 사례
- 2026년 HR 소프트웨어 업계 전반의 공통 화두는 **"알림 피로(notification fatigue)"** — "학습 플랫폼, 성과관리 도구, 협업 소프트웨어가 동시에 주의를 요구하면서 직원들이 우선순위를 정하지 못하고 지쳐간다"는 진단이 반복 등장. 해법으로 제시되는 원칙은 "기술을 더 쓰느냐 마느냐가 아니라, 사람이 실제로 일하는 방식에 맞춰 시스템을 설계했느냐"이다.
- Slack 사용자 리뷰의 최다 불만도 알림 과부하: "채널이 많은 활성 워크스페이스에서는 알림 과부하가 거의 보편적 불만"이며, 세밀한 알림 규칙을 설정하기 어려워 정작 중요한 메시지가 묻힌다.
- NHN두레이는 "공유된 파일·링크·멘션을 모아 보여주는 창이 있어 검색 시간이 상당히 줄어든다"는 점이 강점으로 꼽힘 — 알림/메시지의 사후 검색성이 만족도에 큰 영향.
- 다우오피스: "필독 배지로 최상단 고정" 기능처럼, 전체 알림 중 우선순위를 시각적으로 구분하는 장치가 표준적으로 요구됨.

### 이 앱에 적용 가능한 구체적 개선안
- **[상] 알림 채널·유형별 on/off 설정 페이지** — 사용자가 "결재만 알림, 게시판 알림은 끄기"처럼 개인화할 수 있게 한다. 현재 모바일 탭 배지(`renderMobileTabBadge` 계열)는 미처리 건수만 보여주는데, 유형별 구독 설정이 없으면 알림이 많아질수록 무시당할 위험이 커진다.
- **[상] 공지 "필독"/중요도 배지 + 확인 여부 트래킹** — 인사·안전 공지 등 반드시 읽어야 하는 글에 "읽음 확인" 요구 기능을 추가하고, 미확인자 목록을 관리자가 볼 수 있게 한다(현재 게시판이 단순 목록형이라면 우선순위 표시가 없을 가능성).
- **[중] 알림 다이제스트(일 1회 요약)** — 실시간 알림 대신 급하지 않은 알림(게시판 신규글 등)은 일일 요약으로 묶어 전송해 피로도를 낮춘다.
- **[중] 멘션/파일/링크 통합 검색** — 두레이 사례처럼 "누가 나를 언급했는지, 어떤 파일을 공유했는지"를 한 곳에서 검색 가능하게.
- **[하] 다크모드/텍스트 크기 등 표시 개인화** — 장시간 게시판·결재함을 보는 사무직 사용자 피로도 저감.

## 3. 근태 모듈

### 타 시스템 벤치마크 사례
- 근태 시스템 실사용 후기의 반복 불만: "오래되고 복잡한 시스템이라 HR 업무에 너무 많은 시간이 소요된다", "직원별 연차 내역을 일일이 정리하는 것도 너무 복잡하고 오래 걸린다".
- 외근/영업직 출퇴근 관리의 현실적 어려움: "사원증으로 하니 미소지 이슈가 너무 많고, 영업/외근 인원은 관리가 안 돼 사실상 자율적으로 출퇴근"한다는 실제 운영 사례 — GPS/모바일 체크인이 없는 근태 시스템은 현장에서 무력화된다.
- Workday 비판: "휴가 신청·개인정보 수정 같은 단순 작업에도 너무 많은 클릭이 필요"하다는 것이 가장 흔한 불만 유형 — 근태처럼 고빈도 반복 작업일수록 클릭 수 최소화가 체감 만족도에 직결됨.

### 이 앱에 적용 가능한 구체적 개선안
- **[상] 연차/근태 신청 원터치 플로우** — 휴가 신청을 홈 화면(모바일 하단 탭 "근태")에서 최소 클릭(날짜 선택 → 사유 → 제출)으로 끝나게 하고, 결재선 자동 첨부. Workday의 "다단계 화면" 비판을 반면교사로.
- **[상] 연차 잔여/사용 내역 한눈에 요약** — HR 담당자가 "직원별 연차 내역 일일이 정리"에 시간을 뺏긴다는 불만에 대응해, 부서별/직원별 연차 소진율을 표(엑셀 유사) + 그래프로 자동 집계하는 관리자 화면 강화.
- **[중] 외근/재택 체크인 대응** — 사무실 출근이 아닌 인원(영업/외근)의 근태 인정 방식(모바일 GPS 체크인, 사후 승인)이 있는지 점검. 없다면 "관리 안 되는 인원은 자율 출퇴근"이라는 흔한 실패 패턴을 반복할 위험.
- **[하] 근태 이상 패턴 자동 플래그** — 지각·조퇴 반복, 연차 소진 임박 등을 관리자에게 사전 알림.

## 4. 평가 모듈(KPI·다면평가·승진심사)

### 타 시스템 벤치마크 사례
- 국내 다면평가(360도)의 대표적 실패 패턴: **"형식적 운영"**. "서로에게 의례적으로 좋은 점수만 주는 형식적인 제도"가 되기 쉽고, "피드백을 실질적으로 활용하지 않으면 평가 대상자가 절차로만 받아들인다". 카카오 사례에서는 "조직장이 다면평가 결과를 참고만 할 뿐 본인 원하는 대로 산정할 수 있다"는 직원 불만이 제기된 바 있다 — 즉 **평가 결과가 실제 등급/보상에 얼마나 반영되는지 투명하게 보여주지 않으면 다면평가 자체의 신뢰가 무너진다.**
- 승진심사 불투명성: 잡코리아 조사에서 직장인의 **46.3%가 인사평가에 불만족**, **78.9%가 평가 결과 때문에 이직을 고민**한 적이 있다고 응답. 불만 원인은 "평가 기준 모호", "평가자가 실제 업무를 정확히 모른 채 평가", "보상·승진 결과를 먼저 정해놓고 평가를 역산"하는 관행.
- Personio 리뷰: "360 리뷰 모듈에 개선 여지가 있다", "워크플로우가 경직돼 있어 조직 특성에 맞춰 커스터마이징하기 어렵다"는 불만 — 다면평가 항목/프로세스가 고정형이면 조직 변화에 대응이 안 됨.
- PIP(저성과자 프로그램) 관련 국내 실태: "내부 규칙조차 없이 부서 관리자가 임의로 선별하는 곳이 많아 저성과자로 지목된 사람 대다수가 강하게 반발", 잘못 운영되면 "직장 내 괴롭힘"으로 신고되는 사례까지 발생.

### 이 앱에 적용 가능한 구체적 개선안
이 앱은 이미 KPI/역량/리더십/다면평가, 동점자 처리(`tieNotifications`), 등급비율 설정 등 상용 대비 세밀한 기능을 갖추고 있다(기존 `ERP_HR_벤치마킹_기능격차분석.md` 확인). UX/신뢰 측면 보완점은 다음과 같다.

- **[상] 평가 결과 반영 근거의 투명한 노출** — 다면평가 점수가 최종 등급에 실제로 몇 % 반영됐는지, 1차/2차 평가자 코멘트가 왜 그 등급으로 이어졌는지를 피평가자 화면에서 확인 가능하게. "참고만 하고 마음대로 산정한다"는 카카오식 불신을 피하려면 산정 로직(가중치)을 UI에서 최소한 사후적으로라도 보여줘야 한다.
- **[상] 승진심사 기준 사전 공개** — `renderPromotionPage` 계열에 "이번 승진 대상 기준"(경력연차/등급요건 등)을 승진자 발표 이전, 시즌 시작 시점에 전 직원이 조회 가능한 화면으로 노출. 잡코리아 조사에서 지적된 "기준 모호"에 대한 직접 대응.
- **[중] PIP(저성과자 관리) 선정 기준 문서화 + 이력 관리** — 저성과자 지정 사유, 승인자, 개선 목표, 재평가 일정을 시스템에 구조화해서 남긴다(현재 "인사관리 > 저성과자 관리"가 있다면 사유가 자유서술 텍스트인지, 표준화된 기준표인지 점검 필요). 법적 리스크(부당해고 다툼) 측면에서도 이력 추적 가능성이 중요.
- **[중] 다면평가 익명성 + 코멘트 품질 가이드** — 형식적 답변을 줄이기 위해 서술형 코멘트 입력 시 최소 글자수/구체성 가이드 문구 표시, 극단적으로 짧은 응답에 대한 재작성 유도.
- **[하] 9블록(핵심인재) 결과의 목적별 접근 제한** — 민감정보이므로 열람 권한을 세분화(이미 권한관리 모듈이 있으므로 연계 확인).

- **[하] 저성과자 관리와 평가 모듈 간 데이터 연결** — 4번 섹션의 PIP 개선안과 연동해, 저성과자 지정 이력이 향후 평가 시즌에 자동으로 참조 가능하게.

## 6. 회계 모듈

### 타 시스템 벤치마크 사례
- 국내 ERP 데이터 불일치의 전형적 패턴: "매달 결산이나 재고조사 시점이 되면 영업팀·창고·회계팀이 각자 가진 숫자가 미묘하게 달라 '어느 숫자가 맞는 건가요'부터 다시 확인해야 하는 상황이 반복"된다. 원인은 "전산 입력 오류·누락"과 "현장 관리 부실" 두 축.
- 법인카드 정산은 국내 직장인이 가장 불편해하는 경비 프로세스 1위(응답자의 39%가 "지출증빙 등 후속처리"를 최대 불편으로 꼽음). 회계 담당자 관점에서는 "종이 영수증 처리(38.5%)"가 가장 큰 부담이며, 이어서 지출결의서 처리(30.8%), 전표입력(15.4%) 순.
- 개인카드 경비처리는 "법인카드와 달리 내역을 하나하나 수기로 입력해야 해서 복잡하고 품이 많이 든다"는 지적.
- 회계 자동화(OCR) 실무 조사: 경비 정산 단순입력 업무가 전체 회계업무 시간의 25~30%를 차지하며, OCR 자동화로 이 비율을 5% 이하로 낮추는 것이 목표. 단, "OCR로 추출한 데이터가 회계 프로그램에 자동 반영되지 않으면 절반의 자동화에 그친다"는 경고 — 연동 없는 OCR은 무의미.
- 더존 계열 비판: "기능 문의 시 '제공하지 않는다'는 기계적 답변만 돌아온다"는 지원 불만, 오래된 시스템의 스파게티 코드화 지적(직접적 UX 항목은 아니지만 장기 유지보수성 시사점).

### 이 앱에 적용 가능한 구체적 개선안
- **[상] 영업·재고·회계 간 실시간 잔액 일치 검증 화면** — "각 부서가 다른 숫자를 갖고 있다"는 전형적 실패를 막기 위해, 매출-재고차감-전표 3자 간 합계가 어긋나는 항목을 자동 탐지해 관리자에게 보여주는 대사(reconciliation) 대시보드. 회계 모듈이 "서버 권위형"으로 이미 분리 관리되고 있다면(코드 주석 확인됨) 이 3자 정합성 체크가 자연스러운 다음 단계.
- **[상] 법인카드 지출결의 → 전표 자동 생성 파이프라인** — 직원이 영수증 첨부해 경비 신청 → 전자결재 승인 → 회계 전표 자동 생성까지 이어지는 흐름(기존 격차분석 문서의 "경비정산" 항목과 일치). 국내 직장인 불만 1위 항목이므로 우선순위 최상단에 둘 만함.
- **[중] 영수증 이미지 첨부 시 OCR 금액/거래처 자동 인식(선택적)** — 초기에는 OCR 없이 첨부+수기입력만 지원하더라도, 반드시 "자동 반영"까지 이어지는 설계를 염두에 둘 것(OCR만 붙이고 회계 미연동이면 오히려 반쪽 자동화로 원성을 살 수 있음).
- **[중] 개인카드 경비처리 간소화 폼** — 법인카드 자동 연동 내역과 달리 개인카드/현금 지출은 별도 간이 입력 폼(금액/일자/거래처/용도 4개 필드 정도로 최소화)을 제공해 "수기 하나하나 입력"의 피로를 줄인다.
- **[하] 전표 오류에 대한 구체적 에러 메시지** — "차대변 불일치"라고만 뜨는 대신 "차변 합계 1,200,000 vs 대변 합계 1,150,000 — 50,000원 부족" 처럼 원인+해결 방향을 명시(Toss Tech의 "좋은 에러 메시지 6원칙" — 원인 포함, 해결 대안 포함).

## 7. 영업관리·재고관리 모듈

### 타 시스템 벤치마크 사례
- 영업-재고-회계 연계의 핵심 실패 지점은 "견적 → 매출 → 재고 → 회계"의 각 전환 단계에서 데이터가 **다시 입력**되거나 **누락**되는 것. "영업, 구매, 재고, 회계 데이터가 서로 다른 엑셀/프로그램에 있고 같은 거래처·품목 정보를 여러 파일에 반복 입력한다"는 것이 중소기업 ERP 부재 시의 전형적 증상.
- 안전재고 관리의 흔한 함정: "안전재고·재주문 기준이 담당자 경험에만 의존"하는 경우가 많아 시스템이 자동 계산해주지 않으면 결국 사람 감에 의존하게 됨.
- 다중 창고 이동: "여러 공급망 관리부터 주문 처리 단계까지 한눈에 보이지 않으면 품절, 낮은 재고회전율, 비용증가로 이어진다"는 지적 — 창고 간 이동 이력의 가시성이 핵심.
- 전자구매(eProcurement) 도입 효과 통계: "구매요청 처리시간 50~70% 단축, 평균 구매단가 5~8% 절감, 발주·정산 오류율 80% 감소"라는 업계 벤치마크 수치 — 구매요청 승인 프로세스를 전자화할 때 기대할 수 있는 정량 효과 참고치.
- 중소기업 구매 지연의 근본 원인: "일관성 없는 요청서 양식, 불명확한 승인 절차, 산발적인 인수인계 문서" — 즉 표준화 부재가 지연의 원인이지 승인 단계 자체가 많아서가 아니다.

### 이 앱에 적용 가능한 구체적 개선안
- **[상] 견적서→매출→재고차감→전표 원클릭 연계 상태 표시** — 각 견적 건이 현재 "견적만 발송됨 / 수주됨 / 출고·재고차감됨 / 전표 생성됨" 중 어느 단계인지 배지로 표시하는 파이프라인 뷰. 회계 섹션의 3자 대사와 짝을 이루는 영업 측 가시성 확보.
- **[상] 안전재고 기준값 자동 추천(과거 출고량 기반)** — 현재 `safetyStock` 필드는 존재하지만 값이 수동 설정으로 보인다. 품목별 최근 N개월 평균 출고량 × 리드타임으로 추천값을 계산해 관리자가 "제안값 적용" 버튼으로 채택할 수 있게 하면, "담당자 감에 의존"하는 흔한 실패를 줄일 수 있다.
- **[중] 창고 간 이동 이력의 통합 조회 화면** — 이동 전/후 재고량, 이동 사유, 승인자를 한 화면에서 타임라인으로 볼 수 있게(현재 창고이동 기능은 있으나 이력 가시성 수준 확인 필요).
- **[중] 구매요청서 표준 템플릿 강제** — 품목/수량/희망납기/용도 필드를 필수화해 "일관성 없는 요청서 양식"으로 인한 지연을 방지. 견적서·발주서 폼과 항목 체계를 통일.
- **[하] 발주·정산 오류율 추적 지표** — 구매요청 대비 실제 발주 변경/취소 비율을 월별로 집계해 프로세스 품질을 모니터링(전자구매 도입 효과 벤치마크 수치와 비교 가능하도록).

## 8. PMS(프로젝트·투입률·가동률) 모듈

### 타 시스템 벤치마크 사례
- Monday.com Workload 뷰: "과부하는 빨강, 여유는 초록"으로 즉시 시각화해 "누가 소진 직전인지 실제로 소진되기 전에 보여준다"는 것이 핵심 만족 포인트. 반면 "Resource 컬럼이 Workload 위젯과 연결되지 않는다", "계획 대비 실적(planned vs actual) 집계 뷰가 없다"는 기능적 단절 불만도 존재.
- Float 리뷰: "사용자·데이터가 늘어날수록 성능이 느려지고 스크롤이 버벅인다", "반복 작업/분할/자동 배정 등 태스크 관리가 번거롭다", "프로젝트 수익성에 대한 더 깊은 리포트 분석을 원한다".
- Resource Guru: "드래그앤드롭 스케줄링이 빠르고, 가용성 바·히트맵으로 과다/과소 투입을 한눈에 스캔할 수 있다"는 것이 강점으로 꼽히나, "고급 리포팅·심화 분석은 엔터프라이즈급 대비 제한적"이라는 한계도 지적.
- 국내 IT 프로젝트 실태: "시스템 오픈 전까지 진행 상황을 알 수 없어 중간에 프로젝트가 엇나가도 알아챌 방법이 없다"는 것이 PM들의 핵심 고민. 가동률 80%는 실질적으로 "100%에 가깝다"— 비가동 인력 20%도 제안서 대기·계약 지연·휴가 등으로 실제 즉시 투입 가능 인력은 훨씬 적기 때문에, **가동률 목표치 설정 시 여유율을 고려해야 한다**는 실무 통찰.

### 이 앱에 적용 가능한 구체적 개선안
이 앱은 이미 "내 투입률 입력"(일일 업무 투입 기록 → 월간 자동 집계)과 "가동률 현황"(전체 직원) 화면을 갖추고 있다. 벤치마크 대비 보완점:

- **[상] 과다/과소 투입 색상 경고(Monday.com 벤치마크)** — 가동률 현황(`pms-utilization`) 표에 개인별 월 투입률이 임계치(예: 100% 초과, 50% 미만)를 넘으면 빨강/초록 등 색상 배지로 즉시 식별 가능하게. 현재 표 형태라면 스캔 가능성이 크게 개선됨.
- **[상] 계획 대비 실적(투입 예정 vs 실제 입력) 뷰** — Monday.com이 놓친 지점("계획 대비 실적 집계 없음")을 이 앱은 반대로 강점화할 수 있다. 프로젝트별 예정 투입 인원·기간과 실제 일일 투입 기록을 비교해 괴리를 보여주는 화면.
- **[중] 가동률 목표 설정 시 여유율 가이드 노출** — "가동률 80%가 실질적으로는 100%에 가깝다"는 실무 통찰을 반영해, 목표 가동률 설정 UI에 "제안서 대기·휴가 등 비가동 요인을 감안한 권장 목표치" 안내 문구 추가.
- **[중] 투입률 미입력자 자동 리마인드** — 일일 업무 투입 기록이 방식이 자기입력형이라면, 특정 기간 미입력 시 본인+PM에게 알림(Float가 지적받은 "데이터 최신성 문제"의 예방).
- **[하] 프로젝트별 수익성 연계 리포트** — 투입 인건비(직급별 단가 추정) × 투입시간을 프로젝트 매출과 대조하는 간이 수익성 뷰(Float 사용자들이 원했던 "더 깊은 프로젝트 수익성 분석"에 대응, 다만 우선순위는 낮음 — 회계 모듈의 AR/AP 완성 이후가 적절).

## 9. 권한관리 모듈

### 타 시스템 벤치마크 사례
- RBAC(역할 기반 접근제어)는 "조직 구조나 업무 역할이 비교적 명확한 사내 시스템·ERP·인사관리 시스템에서 직관적이고 관리자 입장에서 이해하기 쉬워 많이 채택"되지만, 실무에서 부딪히는 지점은 **"사람들은 시스템 리소스가 아니라 메뉴 단위로 자신의 업무를 인식한다"**는 점 — 즉 권한 요청이 "이 API에 접근 권한을 달라"가 아니라 "주문 관리 메뉴 접근하게 해달라"는 식으로 온다.
- 화면/UI 컴포넌트 단위의 권한 관리 연구는 상대적으로 드물다는 지적 — 대부분의 사내 시스템은 사용자·역할 분류에만 집중하고, 정작 "이 버튼/이 컬럼이 누구에게 보이는가" 수준의 세밀한 UI 권한 설계는 후순위로 밀린다.

### 이 앱에 적용 가능한 구체적 개선안
- **[상] 메뉴 단위 권한 요청/승인 플로우** — 관리자가 권한을 부여할 때 "role 배열에 문자열 추가" 같은 개발자 시각이 아니라, 현업이 실제로 요청하는 방식인 "이 사람에게 재고관리 메뉴 열어주세요" 식의 메뉴 트리 UI로 권한을 설정/조회할 수 있게. 코드상 각 메뉴 항목에 `roles:["admin","director","leader","member"]`처럼 역할 배열이 이미 붙어있는 구조이므로, 이를 시각화한 "역할별 메뉴 접근 매트릭스" 관리 화면을 추가하는 것이 상대적으로 적은 비용으로 큰 가시성 향상을 가져올 수 있다.
- **[중] 컬럼/필드 단위 마스킹 권한** — 급여·주민등록번호 등 민감 필드는 메뉴 단위가 아니라 필드 단위로 마스킹 권한을 분리(예: 팀장은 팀원 급여 총액은 보되 상세 명세는 못 보게). 기존 격차분석 문서에서도 "개인정보 마스킹 부분적"으로 지적된 부분과 연결.
- **[중] 권한 변경 이력 감사로그 노출 강화** — 활동로그(`renderActivityLog`)가 이미 있으므로, 권한 변경 건만 필터링해 "누가 언제 누구의 권한을 무엇으로 바꿨는지"를 관리자가 바로 조회 가능한 전용 뷰 추가.
- **[하] 임시 권한(기간제 위임)** — 결재 위임처럼, 특정 기간만 상위 권한을 위임하는 기능(예: 팀장 휴가 중 대리자에게 팀 관리 권한 임시 부여).

## 빠르게 적용 가능한 Quick Win 10선

투자 대비 효과가 크고 구현 범위가 상대적으로 작은 항목만 추려 우선순위 순으로 정리했다.

1. **전표 오류 메시지 구체화** — "차대변 불일치" → "차변 1,200,000 vs 대변 1,150,000, 50,000원 부족"처럼 원인+해결 방향 명시 (6번 섹션).
2. **결재 지연 리마인드 알림** — 상신 후 N시간 미처리 시 결재자+상신자에게 알림 배치 1건 추가 (1번 섹션).
3. **가동률 현황 표에 과다/과소 투입 색상 배지** — 기존 표에 조건부 색상만 추가하면 되는 저비용 고효과 항목 (8번 섹션).
4. **안전재고 부족 알림 대시보드 카드를 재고 부족 "추천 발주 수량"까지 확장** — 이미 알림 카드가 존재하므로 확장 개념 (7번 섹션).
5. **알림 유형별 on/off 설정 화면 신설** — 결재/게시판/평가 알림을 개별 토글 (2번 섹션).
6. **게시판 "필독" 배지 + 읽음 확인 트래킹** — 중요 공지의 확인 여부를 관리자가 조회 가능하게 (2번 섹션).
7. **승진심사 기준 사전 공개 화면** — 시즌 시작 시 전 직원 조회 가능한 요건 안내 페이지 (4번 섹션).
8. **개인카드 경비처리 간이 입력 폼** — 금액/일자/거래처/용도 4필드로 최소화 (6번 섹션).
9. **역할별 메뉴 접근 매트릭스 관리 화면** — 기존 `roles` 배열을 시각화만 해도 관리자 UX가 크게 개선 (9번 섹션).
10. **투입률 미입력자 자동 리마인드** — PMS 데이터 최신성 확보를 위한 알림 1건 (8번 섹션).
