# 급여 연계 저장 무결성 후속 점검

대상: HR/ERP, codex/post-merge-integrity-qa, PR #163.
운영 DB·Render 배포·운영 브랜치는 변경하지 않는다.

## 재현 및 수정

- 같은 직원·평가연도의 성과급을 다른 ID로 저장하면 중복 수락되는 것을 임시 JSON 서버에서 재현했다.
- 성과급의 sourceKey를 평가연도와 직원 ID로 검증한다. 같은 지급 근거를 다른 ID로 재등록하는 것을 JSON/PG 공통으로 차단한다. 동일 요청 안의 중복, 동시 요청, 오래된 수정본을 이용한 키 재사용도 검사한다.
- 저장된 마감 월과 확정 급여명세서를 기준으로 급여 조정·명세서의 추가/변경/삭제를 검사한다. 원래 월과 이동 대상 월을 모두 확인한다.
- 같은 요청에 마감 해제와 수정/삭제를 묶어 보내도 이전 마감 상태를 우회할 수 없다. 해제를 먼저 저장한 뒤 별도로 편집한다.
- 거부된 삭제 표식을 제거해 이후 저장에서 다시 삭제되지 않도록 한다. 안전한 다른 항목은 유지하고 거부 사유를 반환한다.
- 화면에 확정/마감 사유를 표시하고 추가·삭제 버튼을 비활성화한다. 삭제 시 화면의 선택 월이 아닌 실제 레코드의 월을 확인한다.
- 월 표현 1과 01을 동일하게 취급한다.
- 실제 브라우저 검증에서 조정 추가 후 편집창이 겹쳐 열려 입력 ID가 중복되는 문제도 발견했다. 동일 편집창을 갱신하도록 수정하고 창이 한 개만 남는지 검사한다.

## 검증

- test/api-payslip-confirmed-protection.test.js: 같은 시나리오를 임시 JSON 및 CI의 별도 PostgreSQL DB에서 실행한다.
- 기존 복리후생 승인→급여 조정, 확정 명세서 복구 거부, 경비→전표 실패 복구·동시 지급 테스트를 함께 실행한다.
- e2e/payroll-persistence.spec.js: 실제 화면에서 조정 항목 추가 → 실제 저장 API → 재조회 → 동료의 급여 확정 → 오래된 화면에서 추가 시도 → 부분 거부 및 화면 원복 → 확정 안내/버튼 비활성화를 검사한다.
- PostgreSQL와 Chromium 결과는 최신 CI 완료 후 판정한다. 테스트 코드 추가만으로 실행 통과를 의미하지 않는다.

## 범위와 남은 과제

이 변경은 급여 저장 무결성에 집중한다. 성과급 계산 공식 전체의 서버 이전, 세금·급여 계산의 법적 정확성 인증, 모든 역할의 평가/반려/재승인 UI 조합까지 완료한 것은 아니다.
기존 중복 운영 자료를 자동 삭제하거나 수정하지 않는다. 기존 성과급 화면의 명시적 중복 정리 절차를 사용한다.
교육 과정 ID 연결, 중첩 이력 민감값 검사, 전체 업무 UI 조합은 기존 후속 계획으로 남는다.
