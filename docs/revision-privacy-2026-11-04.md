# 변경 이력 민감정보·복구 안전성

적용 대상은 record_revisions 및 JSON 수정·삭제 이력 파일이다. 운영 DB, 기존 파일, 별도 AI 앱은 변경하지 않았다.

## 확인된 문제와 처리

- 기존 capSnapshot은 최상위 pw만 제외했다. 2단계 인증 비밀값, 중첩된 토큰·비밀번호·API 키가 이력에 남는 것을 테스트로 재현했다.
- 객체/배열을 재귀적으로 검사하며 알려진 인증정보 키를 대소문자·밑줄·하이픈 변형까지 정규화해 제외한다. 제외한 경로만 기록하고 값은 남기지 않는다.
- 개별 문자열뿐 아니라 총 UTF-8 크기 256 KiB, 노드 10,000개, 깊이 32단계로 제한한다. 큰 데이터가 생략되면 불완전 표시를 남겨 자동 복구를 차단한다.
- 새 저장과 과거 이력 조회 모두 같은 검사를 적용한다. JSON 저널 재처리에도 적용한다.
- 직원 복구는 현재 비밀번호·세션 버전·2단계 인증 설정을 보존한다. 삭제된 직원의 과거 인증정보를 되살리지 않는다.
- 삭제된 직원의 복구가 이전 로그인 토큰을 다시 유효하게 만드는 문제도 실제 API로 재현했다. 새 직원/복구된 직원에는 서버가 새로운 난수 세션 버전을 발급한다. 기존 직원의 정상 세션 버전은 유지한다.
- 그 외 인증정보가 제외된 보관본은 현재 설정을 지울 수 있으므로 미리보기/직접 복구 모두 REVISION_REDACTED(409)로 거절한다. 현재 업무 데이터는 유지한다.

## 검증

- 순수 함수: 중첩 인증정보 제외, 원본 불변, 반복 검사 일관성, 크기·깊이·노드 제한.
- 임시 JSON API: 실제 이력 파일에 비밀값이 없는지, 직원 이름 복구 후 최신 2단계 인증이 유지되는지, 제외된 보관본의 복구가 거절되는지 검사.
- 임시 PostgreSQL: 새 이력 원본 검사, 구형 민감정보 포함 이력 주입 후 미리보기/직접 복구 차단과 현재 자료 유지 검사.
- JSON/PG: 직원 삭제 후 복구해도 삭제 전 로그인 토큰이 401로 계속 차단되는지 검사한다.
- 기존 복구 권한·확정 급여 보호·동시 수정 충돌·저널 복구 테스트 유지. 최종 통과 여부는 PR의 최신 CI 결과를 따른다.

## 한계와 남은 범위

- 알려진 필드 이름 기반 검사다. 자유서술 본문에 직접 적힌 비밀번호나 임의 이름의 필드까지 식별하는 기능은 아니다.
- 기존 디스크/DB에 이미 보관된 비밀값을 자동 삭제하지 않는다. 조회·복구 경로를 보호하며, 기존 자료 정리는 별도 영향 확인과 백업이 필요하다.
- 연간 스냅샷, employee_history/kpi_history, 외부 백업은 별도 저장소이며 이번 수정으로 전체 삭제·마스킹되었다고 해석하면 안 된다.
- 이력 보관 정책·정리 미리보기 및 다른 이력 저장소의 민감정보 제거는 후속 범위다.

## 후속: 일반 직원 저장과 2단계 인증

- 직원 이름을 수정해 저장하면 GET /data에서 숨겨진 twoFactorSecret이 삭제되는 것을 JSON API로 재현했다. 관리자 저장도 포함해 일반 직원 저장은 서버의 기존 인증 설정을 보존한다. 요청에 임의 비밀값이나 해제 플래그를 넣어도 적용하지 않는다.
- /api/auth/2fa/settings 전용 경로는 세션의 본인 계정만 선택하고 현재 비밀번호와 OTP를 확인한다. 해제는 클라이언트가 제출한 비밀값이 아니라 서버 저장값으로 검증한다.
- 검증과 저장은 회사 저장 잠금 안에서 수행하고 세션 버전을 다시 확인한다. 인증 설정 변경 시 이전 세션을 철회하며 성공 응답에 새 토큰을 반환한다. 동시에 도착한 같은 세션의 변경은 하나만 성공한다.
- 등록용 키 발급도 로그인된 본인 계정만 허용한다. 구형 verify-code는 순수 코드 검사만 유지하며 인증 설정을 저장하지 않는다.
- 화면은 서버 성공 응답 후에만 완료를 표시한다. 새로고침 후에도 현재 비밀번호와 OTP로 해제할 수 있고 비밀값을 직원 목록에 넣어 자동 저장하지 않는다.
- 기존 브라우저는 새로고침해야 한다. 구형 화면이 일반 /save로 인증 설정을 변경하는 동작은 더 이상 지원하지 않는다. 인증 앱 분실 복구 절차는 이번 범위가 아니다.
- JSON 인증·복구 회귀 25건과 문법 검사를 통과했다. PostgreSQL 공통 시나리오와 새로고침 후 해제하는 Chromium 시나리오를 추가했으며 최신 PR CI로 결과를 확인한다.
